# 노드 -> DOM 트리 변환 과정

## 토큰이 들어왔을때 브라우저 파서가 노드 인스턴스를 만들고 파싱 스택(Parsing Stack)을 이용해 DOM트리로 조립하는 과정을 단계별로 나타냈다.

위의 간단한 HTML 조각이 방출하는 토큰 스트림을 예시로 살펴보자.

```html
<div><p>안녕</p></div>
```

### 이 코드는 토큰화를 거치며 다음 5개의 토큰으로 나뉜다.

    1. StartTag: div
    2. StatTag: p
    3. Character: "안녕"
    4. EndTag: p
    5. EndTag: div

### 조립 알고리즘의 핵심 규칙 (스택 기반)
    - StartTag 토큰
        1. 메모리에 새 C++ 노드 인스턴스를 생성합니다.
        2. 현재 스택의 맨 위(Top)에 있는 노드를 부모에 삼아 자식 포인터로 연결합니다.
        3. 방금 만든 노드를 스택에 Push합니다. (이제 이 노드가 새로운 부모 후보가 됨).
    - Charracter 토큰
        1. 텍스트 노드(TextNode) 인스턴스를 생성합니다.
        2. 현재 스택 맨 위(Top)노드의 자식으로 연결합니다.(텍스트는 자식을 가질 수 없으므로 스택에 넣지 않음)
    - EndTag 토큰
        1. 해당 태그가 닫혔으므로 스택에서 Pop하여 제거합니다.

### 단계별 스택과 트리 메모리 상태 변화 과정

초기 상태

브라우저는 항상 최상위 관리 노드인 Document를 기본 생성하고 스택에 넣어둔 채 시작한다.

```md
[파싱 스택]
| Document |  <- Top

[메모리 상의 트리]
Document
```
---------------------------------------------------------

1단계 : StartTag: div 도착
    - HTMLDivElement 노드 인스턴스를 생성합니다.
    - 스택 Top인 Document의 자식으로 div를 연결합니다.
    - div를 스택에 Push합니다.

```md
[파싱 스택]
| div      |  <- Top
| Document |

[메모리 상의 트리]
Document
   └── div
```
---------------------------------------------------------

2단계 : StartTag: p도착
    - HTMLPargraphElement 노드 인스턴스를 생성합니다.
    - 현재 스택 Top인 div의 자식으로 p를 연결합니다.
    - p를 스택에 Push합니다.
    
```md
[파싱 스택]
| p        |  <- Top
| div      |
| Document |

[메모리 상의 트리]
Document
   └── div
        └── p
```
---------------------------------------------------------

3단계 : Character: "안녕" 도착
    - TextNode("안녕")인스턴스를 생성합니다.
    - 현재 스택 Top인 p의 자식 포인터로 연결합니다. (스택 Push 안함)
```md
[파싱 스택]
| p        |  <- Top
| div      |
| Document |

[메모리 상의 트리]
Document
   └── div
        └── p
             └── "안녕" (TextNode)
```
---------------------------------------------------------
4단계 : EndTag: p 도착
    - p 태그 영역이 끝났으므로 스택에서 p를 Pop합니다.
    - 트리 구조는 그대로 유지되며, 스택의 Top은 다시 div로 복귀합니다.
```md
[파싱 스택]
| div      |  <- Top
| Document |

[메모리 상의 트리]
Document
   └── div
        └── p
             └── "안녕"
```
---------------------------------------------------------
5단계 : EndTag: div 도착
    - div 태그 영역이 끝났으므로 스택에서 div를 Pop합니다.
```md
[파싱 스택]
| Document |  <- Top

[메모리 상의 트리 (최종 완성된 DOM 트리)]
Document
   └── div
        └── p
             └── "안녕"
```
---------------------------------------------------------

C++ 메모리 관점에서의 실제 모습
    - 실제 브라우저 C++ 힙 메모리에서는 이 구조가 노드 객체들 간인 포인터(주소값)연결로 구현되어 있습니다.
```md
[ Document 인스턴스 ]
   - firstChild ─────────┐
                         ▼
                  [ DivElement 인스턴스 ]
                    - parentNode ──> Document
                    - firstChild ──┐
                                   ▼
                            [ ParagraphElement 인스턴스 ]
                              - parentNode ──> DivElement
                              - firstChild ──┐
                                             ▼
                                      [ TextNode ("안녕") ]
                                        - parentNode ──> ParagraphElement
```
---------------------------------------------------------

파서가 선형적으로 들어오는 토큰들을 스택 이라는 LIFO(후입선출) 구조를 활용해 처리함으로써, 깊이 중첩된 계층 관계를 가진 트리(Tree) 포인터 구조로 변환해 내는 원리이다.
