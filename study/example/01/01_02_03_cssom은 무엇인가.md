# CSSOM

## CSSOM(CSS Object Model) : CSSOM은 브라우저가 CSS 코드르르 파싱하여 자바스크립트나 브라우저 엔진이 이해하고 조작할 수 있도록 만든 객체 트리 구조이다.

HTML을 파싱해 DOM(Document Object Model)을 만들듯, 브라우저는 `<link>`,`<style>`, 인라인 스타일 등으로 전달된 CSS를 읽고 CSSOM트리를 생성합니다.

예를 들어 다음과 같은 style.css이 있다면
```css
body { font-size: 16px; }
.container { text-align: center; }
.container h1 { color: blue; }
.btn { display: none; }
```

1단계: CSS파일 비동기 요청과 CSS 파싱
HTML 파서가 `<link>` 태그를 만나면 브라우저는 네트워크 스레드를 통해 css/style.css 파일을 요청합니다.
- 이때 HTML 파싱은 멈추지 않고 계속 진행되어 아래쪽의 `<body>`, `<div class="container>`등의 DOM 노드를 계속 만듭니다.  
- CSS 파일이 도착하면, HTML과 똑같은 파이프라인(바이트 -> 문자 -> 토큰 -> 노드 -> CSSOM트리)를 거쳐 파싱됩니다.

2단계: CSSOM 트리 생성과 스타일 상속(Cascading)
CSS 파서가 위 텍스트를 읽어서 부모의 스타일이 자식으로 대물림(Cascading)되는 규칙이 반영된 CSSOM(CSS Object Model)트리를 메모리에 구축합니다.

```md
[메모리 상의 CSSOM 트리]
      body (font-size: 16px)
        │
        ├── .container (font-size: 16px [상속됨], text-align: center)
        │       └── h1 (font-size: 16px [상속됨], text-align: center [상속됨], color: blue)
        │
        └── .btn (font-size: 16px [상속됨], display: none)
```

3단계: DOM + CSSOM = 렌더 트리(Render Tree)결합
메모리에 DOM 트리(구조)와 CSSOM 트리(스타일)가 모두 준비되면, 브라우저 렌더링 엔진은 두 트리를 결합하여 렌더 트리(Render Tree)라는 새로운 트리를 만든다.
```md
[DOM 트리]                         [CSSOM 트리]
Document                             body (16px)
 └── html                             ├── .container (center)
      ├── head (메타태그, 타이틀)       │     └── h1 (blue)
      └── body                        └── .btn (display: none)
           └── div.container
                ├── h1 ("카운터 실습")
                ├── p ("현재 숫자: 0")
                └── button.btn ("숫자 올리기")

```
▼ 결합 및 필터링 (Matching & Filtering) ▼

```md
[완성된 Render Tree (Layout Tree)]
RenderView (최상위 화면)
 └── RenderBlock (body) ────────── [font-size: 16px]
      └── RenderBlock (div.container) ── [font-size: 16px, text-align: center]
           ├── RenderText (h1) ───────── [color: blue, text: "카운터 실습"]
           └── RenderBlock (p) ───────── [font-size: 16px, text: "현재 숫자: 0"]
           (※ head 태그와 display: none인 button.btn은 아예 제외됨!)
```
- 필터링 : DOM 트리에 있던 `<head>`, `<meta>`, `<title>`, `<script>`처럼 원래 시각적 형태가 없는 노드들과, CSS에서 display: none이 적용된 노드는 렌더 트리에서 완전히 제외됩니다. (참고로 visibility : hidden은 공간은 차지하므로 렌더 트리에 포함된다.)
- 매칭 : 살아남은 각 DOM 노드에 대해 CSSOM 트리를 뒤져서 일치하는 선택자 규칙을 찾아 스타일 구조체를 붙입니다.

4단계: 레이아웃(Layout / Reflow) - 기하학적 계산

렌더 트리가 완성되었지만, 아직 각 노드가 화면의 어느 좌표(x,y)에 얼마만한 크기(width, height)로 그려져야 하는지는 계산되지 않았다.
- 브라우저는 렌더 트리의 루트부터 순회하면서, 현재 브라우저 창 크기(viewport)를 기준으로 모든 노드의 정확한 픽셀 위치와 박스 모델(Margin, Padding, Border) 크기를 수학적으로 계산합니다.
- 상대 단위( % , rem , vw)들이 이 단계에서 모두 절대적인 픽셀(px)좌표값으로 변환합니다.

5단계: 페인트(paint)와 컴포지팅(COmpositing) - 픽셀 찍기
1 페인팅(paint) : 계산된 좌표와 스타일 정보(배경색, 글자색, 테두리, 그림자 등)를 바탕으로 실제 화면에 그릴 그리기 명령어 목록(Paint Records)을 만듭니다.
2 레스터화(Rasterization) 및 합성(Compositing) 
- 이 명령어 들은 GPU로 넘겨 실제 색상 픽셀(비트맵)로 변환합니다.
- 복합적으로 요소들은 포토샵의 레이어처럼 여러 층으로 나누어 그린 뒤 하나로 합쳐 모니터 화면에 최종 출력합니다.



## 전체적인 동작 방식 및 특징
(동작 방식 및 특징)

1. 트리 구조 구축
    CSS의 캐스케이딩(Cascading)규칙과 상속 관계를 반영한다.

    cf) CSS의 캐스케이딩(Cascading)은 여러 개의 스타일 규칙이 하나의 HTML 요소에 동시에 접용될 때, 어떤 스타일을 우선으로 적용할지 결정하는 알고리즘(우선순위 규약)

2. 렌더 트리(Render Tree)생성의 필수 요소
    브라우저는 화면에 실제 요소를 그리기 전에 DOM과 CSSOM을 결합하여 화면에 실제로 표시될 요소들의 구조와 스타일 정보를 담은 렌더 트리를 만든다.
        

    visibility: hidden 또는 opacity:0은 눈에만 보이지 않을 뿐, 요소가 가진 크기(width,height)만큼의 빈 공간을 그대로 차지한다. 이 빈 공간 때문에 주변 다른 요소들의 배치 위치가 달라지므로, 브라우저는 레이아웃을 정확하게 계산하기 위해 이 요소를 렌더트리에 반드시 포함시켜야 한다.

    아래처럼 작성시 display를 none으로 작성하여 화면에 그릴 필요가 없어 렌더 트리에서 제외된다.

```html
<p>보이는 텍스트</p>
<span style="display: none;">숨겨진 텍스트</span>
```

3. 렌더링 차단 리소스(Render-Blocking)
    불완전한 스타일 상태로 화면이 그려지는 현상(FOUC, Flash of Unstyled Content)을 막기 위해, 브라우저는 CSSOM 생성이 완료될 때까지 화면 렌더링을 차단한다.

4. 자바스크립트를 통한 조작
    자바스크립트에서 element.style.color = 'red'나 window.getComputedStyle(element) 등의 API를 호출할 때 CSSOM에 접근하여 수정하게 된다. (CSSOM 또는 계산된 스타일 정보에 접근하여 수정)
