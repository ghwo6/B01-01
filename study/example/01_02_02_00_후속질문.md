# HTML 파싱

## 바이트 -> 문자로 변경

인코딩 설정에 따라 원시 바이트 스트리을 실제 문자열로 변환한다.

ex 문자 : 3C 68 74 6D 6C 3E,

ex 인코딩 설정 : (UTF-8) ,

ex 실제 문자열 : `<html>`, `<body>`

## 문자 -> 토큰 [어휘 분석. Lexing]

연속된 문자열을 문법적 의미를 갖는 최소 단위(토큰)로 쪼갭니다.

시작 태그(StartTag: html), 종료 태그(EndTag: head), 속성(Attribute: id='number'), 문자 데이터(Character: 카운터 실습)등으로 분류된 토큰 객체가 생성됩니다.

### 보충 설명

`<p class="txt">`안녕`</p>`를 문자로 보면

['<', 'p', ' ', 'c', 'l', 'a', 's', 's', '=', '"', 't', 'x', 't', '"', '>', '안', '녕', '<', '/', 'p', '>'] 와 같이 나온다.

이를 html 파서 내부에 있는 상태 머신이 글자를 익을 때마다 현재 모드(상태)를 전환한다.

    1. 데이터 상태(Data tate) : 일반 글자를 읽는 기본 상태
    2. < 글자를 만남 -> "태그가 시작되겠네" 태그 오픈 상태(Tag Open State)로 전환한다.
    3. p 글자를 만남 : 태그 이름을 수집하는 상태로 들어가 토큰의 이름을 p로 기록한다.
    4. 공백( )을 만남 : 태그 이름이 끝났음을 알고, 속성(Attribute)을 찾을 준비를 한다.
    5. class="txt"를 만남 : 속성 이름과 값을 파싱하여 토큰 내부에 맵(key-value) 형태로 저장한다.
    6. > 글자를 만남 : "시작 태그 하나가 완성되었다"라고 판단하고 하나의 완성된 StartTag 토큰을 방출(Emit)한 뒤 다시 데이터 상태로 돌아간다.
    7. 안녕을 읽음 : 화면에 찍힐 글자이므로 Character 토큰(안녕)으로 묶어 방출한다.
    8. `</`를 만남 : 종료 태그임을 감지하고 p`>`까지 읽은 뒤 EndTag 토큰(p)을 방출한다.

예시

입력 (연속된 문자 배열) :

```html
<p class=\"txt\">안녕</p>
```

출력 (토큰 객체 스트림) :

```json
[
  { "type": "StartTag", "name": "p", "attributes": { "class": "txt" } },
  { "type": "Character", "data": "안녕" },
  { "type": "EndTag", "name": "p" }
]
```

### 이 과정이 필수적인가?

문자 -> 토큰으로 변경하지 않고 바로 트리를 만들려고 하면 연산이 복잡해진다.

자음과 모음등을 조합하지 않고 파악하는것과 같다.

문자 : `<`, d, i, v, `>`

토큰 - 의미가 부여된 단어 객체 : [StartTag : div]

## 노드 -> DOM 트리(DOM Tree)

토큰이 순차적으로 방출될 때 브라우저 파서는 내부적으로 토큰화 스택(Token Stack)을 사용한다.

예를 들어 StartTag: div를 만나면 스택에 푸시하고 노드를 생성해 현재 부모 노드의 자식으로 연결한다.
이후 EndTag: div를 만나면 스택에서 팝하여 닫힌다.

이 과정을 통해 부모 - 자식 - 형제 관계가 포인터로 연결된 N진 트리(N-ary Tree)자료구조가 완성됩니다.
