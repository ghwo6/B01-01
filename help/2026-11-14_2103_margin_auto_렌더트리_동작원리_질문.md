# `margin-right: auto`와 Flexbox 레이아웃 계산 원리

- 일시: 2026-11-14 21:03
- 질문: `.logo`에 `margin-right: auto`를 줬을 때, 상하(상속) 관계도 아닌데 `<header class="header">` 안의 `<nav>`, 버튼들까지 같이 오른쪽 끝으로 밀려 나오는 이유가 무엇인가? 렌더 트리 만들고 레이아웃할 때 `<nav> <ul> <li>` 등의 `px` 값까지 먼저 계산한 다음 위치시켜서 그런 건가?

---

## 1. 결론부터

**네, 맞습니다.** 위치가 "상속"되는 것이 아니라, 브라우저가 **레이아웃(Layout) 단계에서 형제 요소들의 실제 크기(`px`)를 먼저 전부 계산한 뒤, 남는 공간을 `auto` 여백에 몰아주기 때문**입니다.

---

## 2. 브라우저가 `<header>`를 배치하는 순서

1. **DOM 트리 + CSSOM 트리 → 렌더 트리(Render Tree) 생성**
   - 화면에 실제로 그려질 요소들과 각 요소에 적용될 CSS 규칙이 합쳐집니다.
2. **레이아웃(Layout / Reflow) 단계 — 정확한 `px` 크기와 좌표 계산**
   - `<header class="header">`에 `display: flex`가 적용되어 있으므로, 브라우저는 **Flexbox 레이아웃 규칙**에 따라 아래 순서로 계산합니다.

   1. **안쪽 자식 크기부터 측정:** `<nav>` 안에 있는 `<ul>`, `<li>`, `<a>` 글자들의 크기를 먼저 계산해 `<nav>`의 전체 너비(`px`)를 확정합니다.
   2. **모든 직계 자식 너비 합산:** `.logo`, `.nav`, `.theme-toggle`, `.hamburger` 각각의 너비와 `gap`을 모두 더합니다.
   3. **남는 여유 공간 계산:**
      ```text
      남는 공간 = header 전체 너비 - (모든 자식들의 너비 합 + gap 합)
      ```
   4. **`margin-right: auto`에 남는 공간 몰아주기:** Flexbox에서는 `margin`에 `auto`가 지정되어 있으면 위에서 구한 **남는 공간 전부**를 그 마진의 `px` 값으로 채웁니다.
   5. **왼쪽부터 차례대로 배치:**
      ```text
      [.logo] + [남는 공간 전부(margin-right: auto)] + [.nav] + [.theme-toggle] + [.hamburger]
      ```
      `.logo` 바로 오른쪽에 남는 공간 전체가 벽처럼 들어가므로, 그 뒤에 줄 서 있던 형제 요소들(`.nav`, 버튼들)이 **자연스럽게 오른쪽 끝까지 밀려나서** 나란히 붙게 됩니다.

---

## 3. 왜 고정값(`px`) 대신 `auto`를 쓸까?

| 방식 | 동작 | 창 크기를 줄였을 때 |
|---|---|---|
| `margin-right: 500px;` | 무조건 500px를 비움 | 뒤의 메뉴·버튼들이 **화면 오른쪽 밖으로 뚫고 나감** |
| `margin-right: auto;` | **전체 너비 - 형제들 너비 합**만큼만 비움 | 남는 공간만 자연스럽게 줄어들어 **겹치기 직전까지 안전하게 유지**됨 |

---

## 4. 핵심 정리

- `margin-right: auto`가 형제들에게 값을 "상속"하는 것이 아닙니다.
- **`display: flex`라는 한 줄 공간 안에서, 모든 형제 요소의 `px` 크기를 먼저 계산한 뒤 남은 빈칸을 `.logo` 오른쪽 마진에 전부 배분**하기 때문에 뒤에 있는 요소들이 오른쪽 끝으로 함께 정렬됩니다.
- 참고: `display: flex`가 아닌 일반 `block` 배치에서는 `margin-right: auto`를 줘도 형제들이 같은 줄 오른쪽으로 밀리지 않고 다음 줄에 놓입니다. **Flexbox와 결합했을 때만** 이렇게 한 줄에서 좌우로 벌리는 효과가 납니다.
