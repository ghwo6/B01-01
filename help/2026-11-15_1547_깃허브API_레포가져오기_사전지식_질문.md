# GitHub API로 내 레포지토리 가져오기 전 필수 문법 & 지식

- 일시: 2026-11-15 15:47
- 질문: GitHub API로 내 레포지토리를 가져오는 기능을 구현해 보려고 하는데, 시작하기 전에 꼭 알아야 할 문법과 기초 지식들을 알려줘.

---

## 1. API와 JSON부터 눈으로 확인하기

* **API:** 다른 서버(GitHub)에게 "내 저장소 목록 데이터 좀 줘"라고 요청할 수 있는 약속된 주소입니다.
  ```text
  https://api.github.com/users/{본인_깃허브_아이디}/repos
  ```
* **JSON:** 서버가 돌려주는 데이터 형식입니다. 자바스크립트의 **배열(`[ ... ]`) 안에 객체(`{ ... }`)들이 들어있는 모양**과 거의 똑같습니다.
* **먼저 해 볼 것:** 코드를 짜기 전에 **Chrome 주소창에 위 주소를 직접 입력해 보세요.** 내 저장소 정보가 어떤 이름(`name`, `description`, `language`, `stargazers_count`, `html_url`)으로 들어있는지 바로 볼 수 있습니다.

> ⚠️ **레이트리밋 주의 (`todolist.md` 0단계):**
> 로그인 없이 요청하면 **1시간에 60회**로 제한됩니다. 60회를 넘기면 `403` 에러가 뜨니, 개발 중 짧은 시간에 새로고침(F5)을 너무 여러 번 누르지 않도록 주의하세요.

## 2. 비동기 처리: `fetch`, `async`, `await` (`todolist` 8단계)

네트워크로 데이터를 가져오는 일은 시간이 걸립니다. 자바스크립트는 기다리지 않고 다음 줄을 실행하려 하기 때문에 **"기다렸다가 받아라"**라고 표시해 줘야 합니다.

```javascript
const fetchRepos = async () => {
    const response = await fetch('https://api.github.com/users/아이디/repos');
    const data = await response.json();
    console.log(data);
};
```

| 키워드 | 역할 |
|---|---|
| `async` | "이 함수 안에서는 비동기 작업(`await`)을 기다릴 것이다"라는 표시 (함수 앞에 붙임) |
| `await` | 뒤의 작업이 끝날 때까지 다음 줄로 넘어가지 않고 기다림 (`async` 함수 안에서만 사용 가능) |
| `fetch(url)` | 해당 주소로 네트워크 요청을 보냄 → 응답 객체(`response`) 반환 |
| `response.json()` | 응답 본문(JSON 글자)을 **자바스크립트 배열/객체로 변환** (시간이 걸리므로 `await` 필수) |

## 3. 에러 처리: `try / catch`와 `response.ok`

```javascript
try {
    const response = await fetch(url);
    if (!response.ok) {
        throw new Error(`HTTP 오류: ${response.status}`); // 403, 404 등 직접 에러 발생
    }
    const repos = await response.json();
} catch (error) {
    // 네트워크 끊김 또는 위에서 throw한 에러가 모두 여기로 옴
}
```

* **꼭 알아야 할 함정:** `fetch`는 인터넷이 아예 끊겼을 때만 자동으로 `catch`로 갑니다. **없는 아이디(`404`)나 레이트리밋 초과(`403`)**는 서버가 응답을 주긴 했으므로 `catch`로 가지 않습니다!
* 그래서 반드시 **`if (!response.ok)`를 확인하고 `throw new Error(...)`로 에러를 던져야** `catch`에서 잡아낼 수 있습니다.

## 4. ES6+ 필수 문법 3가지 (`todolist` 7단계)

### ① 구조분해 할당 (Destructuring)
객체에서 필요한 속성만 깔끔하게 꺼내는 문법입니다.
```javascript
// 일일이 repo.name, repo.html_url 쓰지 않고 한 번에 꺼내기
const { name, description, html_url, stargazers_count, language } = repo;
```

### ② 기본값 처리 (`||` 또는 `??`)
레포지토리에 설명이나 주 언어가 비어 있으면 GitHub API가 **`null`**을 줍니다. 그대로 화면에 넣으면 글자 `"null"`이 출력되므로 기본 문구를 넣어 줍니다.
```javascript
const descText = description || '설명이 없습니다.';
const langText = language || '기타';
```

### ③ 템플릿 리터럴 (Template Literal)
작은따옴표(`'`) 대신 **백틱(`` ` ``)**을 쓰면 줄바꿈이 자유롭고 `${변수}`로 값을 끼워 넣을 수 있습니다.
```javascript
const cardHtml = `
    <article class="project-card">
        <h3>${name}</h3>
        <p>${descText}</p>
        <span>${langText} · ★ ${stargazers_count}</span>
        <a href="${html_url}" target="_blank">저장소 보기</a>
    </article>
`;
```

## 5. 배열 메서드: `map`, `join`, `filter` (`todolist` 7단계)

API로 받은 `repos`는 여러 개의 저장소가 담긴 **배열**입니다. 이걸 화면에 카드로 바꾸려면 배열 메서드를 씁니다.

* **`map(...)`:** 배열의 각 항목을 다른 모양(HTML 문자열)으로 1:1 변환합니다.
* **`join('')`:** 문자열들이 담긴 배열을 **하나의 큰 문자열로 합칩니다.**
  > ⚠️ **흔한 실수:** `.join('')`을 빼먹고 `innerHTML`에 배열을 그대로 넣으면 카드와 카드 사이에 **쉼표(`,`)**가 화면에 찍힙니다!
* **`filter(...)` (선택):** 조건에 맞는 항목만 남깁니다. (예: 포크한 레포 빼기 `repos.filter(repo => !repo.fork)`)

```javascript
const cardsHtml = repos
    .map((repo) => `<li>${repo.name}</li>`)
    .join('');
```

## 6. 4가지 UI 상태와 상태 관리 패턴 (`todolist` 8~9단계)

API를 부를 때는 항상 4가지 상황이 생길 수 있으며, 이를 `state` 객체로 관리하면 React의 `state` 개념을 자연스럽게 익힐 수 있습니다.

| 상태 (`status`) | 언제 발생하나 | 화면에 보여 줄 것 |
|---|---|---|
| **`loading`** | `fetch` 요청을 보낸 직후 | 스피너 또는 `"로딩 중..."` |
| **`success`** | 데이터 수신 성공 & 1개 이상 있음 | 카드 목록 렌더링 |
| **`empty`** | 데이터 수신 성공했지만 빈 배열(`[]`) | `"표시할 프로젝트가 없습니다."` |
| **`error`** | `403`, `404`, 네트워크 오류 발생 | `"프로젝트를 불러올 수 없습니다."` + **`[다시 시도]` 버튼** |

### 흐름 잡기 (이벤트 → 상태 변경 → `render()` 호출)
```javascript
const state = {
    status: 'loading', // 'loading' | 'success' | 'empty' | 'error'
    repos: [],
};

const render = () => {
    // state.status 값에 따라 if / else if 로 #projects 안의 내용을 바꿔 그림
};
```
* **주의 (`todolist` 0단계):** 에러 화면에 `[다시 시도]` 버튼을 `innerHTML`로 넣더라도, HTML 안에 `onclick="fetchRepos()"`를 쓰면 **금지 규칙**에 걸립니다. 버튼을 그린 **직후에** `document.querySelector('.retry-btn').addEventListener('click', fetchRepos)`로 연결하세요.
