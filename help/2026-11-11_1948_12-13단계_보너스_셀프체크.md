# 12단계. 보너스 과제

## 1. 언어별 필터링 버튼 (`array.filter()`)
7~9단계 가이드 6번의 확장판입니다. **필터도 "상태 → 렌더링"으로** 만듭니다.

### HTML
```html
<section id="projects">
    <h2>Projects</h2>
    <div class="filter-buttons"></div>   <!-- JS가 버튼을 채움 -->
    <div class="project-status" aria-live="polite"></div>
    <div class="project-list"></div>
</section>
```

### JS
```js
const filterEl = document.querySelector(".filter-buttons");

projectState.filter = "All";

// 저장소들에서 언어 목록 뽑기 (중복 제거 + null 제외)
const getLanguages = () => [
    "All",
    ...new Set(projectState.repos.map((repo) => repo.language).filter(Boolean)),
];

const getVisibleRepos = () =>
    projectState.filter === "All"
        ? projectState.repos
        : projectState.repos.filter((repo) => repo.language === projectState.filter);

const renderFilters = () => {
    filterEl.innerHTML = getLanguages()
        .map(
            (lang) => `
            <button type="button"
                    class="filter-btn ${lang === projectState.filter ? "active" : ""}"
                    data-lang="${lang}">
                ${lang}
            </button>`
        )
        .join("");
};

// 이벤트 위임: 버튼은 나중에 생기므로 부모에 이벤트
filterEl.addEventListener("click", (event) => {
    const button = event.target.closest(".filter-btn");
    if (!button) return;

    projectState.filter = button.dataset.lang; // 상태 변경
    renderFilters();                            // 렌더링
    renderProjects();
});
```
- `renderProjects()`의 성공 분기에서 `repos` 대신 `getVisibleRepos()`를 사용합니다.
- `fetchProjects()` 성공 직후 `renderFilters()`도 한 번 호출합니다.
- `new Set(...)`: 중복을 없애 주는 자료구조입니다. `...`(스프레드)로 다시 배열로 펼칩니다.
- `data-lang="..."` ↔ `button.dataset.lang`: HTML에 데이터를 심어 두고 JS에서 꺼내는 방법입니다.

```css
.filter-btn.active {
    background-color: var(--color-primary);
    color: #ffffff;
}
```

## 2. Hero 타이핑 효과 (한 글자씩 나타나기)

### HTML
```html
<h1>안녕하세요! <span class="typing"></span></h1>
```

### JS
```js
const typingEl = document.querySelector(".typing");
const TYPING_TEXT = "김호재라고 합니다.";
const TYPING_SPEED = 120; // ms

let index = 0;

const typeNext = () => {
    typingEl.textContent = TYPING_TEXT.slice(0, index + 1);
    index += 1;

    if (index < TYPING_TEXT.length) {
        setTimeout(typeNext, TYPING_SPEED);
    }
};

typeNext();
```
- `slice(0, n)`: 앞에서부터 n글자까지 자릅니다.
- `setTimeout`으로 자기 자신을 다시 부르며 한 글자씩 늘립니다.

### 깜빡이는 커서 (CSS)
```css
.typing::after {
    content: "|";
    margin-left: 2px;
    animation: blink 0.8s step-end infinite;
}

@keyframes blink {
    50% { opacity: 0; }
}
```

### (응용) 여러 문장 번갈아 쓰고 지우기
```js
const PHRASES = ["김호재입니다.", "호기심이 많습니다.", "원리를 좋아합니다."];
let phraseIndex = 0;
let charIndex = 0;
let isDeleting = false;

const loop = () => {
    const current = PHRASES[phraseIndex];
    charIndex += isDeleting ? -1 : 1;
    typingEl.textContent = current.slice(0, charIndex);

    let delay = isDeleting ? 60 : 120;

    if (!isDeleting && charIndex === current.length) {
        isDeleting = true;
        delay = 1500;                 // 다 쓰고 잠깐 멈춤
    } else if (isDeleting && charIndex === 0) {
        isDeleting = false;
        phraseIndex = (phraseIndex + 1) % PHRASES.length; // 다음 문장
        delay = 400;
    }

    setTimeout(loop, delay);
};

loop();
```

## 3. 폼 실제 전송 (Formspree)
EmailJS보다 설정이 간단한 Formspree 기준입니다. 외부 라이브러리를 설치하는 게 아니라 **`fetch`로 요청만 보내므로** 0번 규칙에 걸리지 않습니다.

1. https://formspree.io 가입 → **New Form** 생성
2. 발급된 주소 복사: `https://formspree.io/f/xxxxxxx`
3. 6단계 폼의 `submit` 핸들러에서 **검증 통과 후** 전송

```js
const FORM_ENDPOINT = "https://formspree.io/f/xxxxxxx";

form.addEventListener("submit", async (event) => {
    event.preventDefault();

    // ... 6단계 검증 코드 ...
    if (!isValid) return;

    const submitBtn = form.querySelector('button[type="submit"]');
    submitBtn.disabled = true;           // 중복 클릭 방지
    submitBtn.textContent = "전송 중...";

    try {
        const response = await fetch(FORM_ENDPOINT, {
            method: "POST",
            headers: { Accept: "application/json" },
            body: new FormData(form),    // name 속성 기준으로 값이 담김
        });

        if (!response.ok) throw new Error("전송 실패");

        successMessage.textContent = "메시지가 전송되었습니다. 감사합니다!";
        form.reset();
    } catch (error) {
        successMessage.textContent = "전송에 실패했습니다. 잠시 후 다시 시도해 주세요.";
    } finally {
        submitBtn.disabled = false;
        submitBtn.textContent = "보내기";
    }
});
```
- `FormData`는 `<input name="...">`의 **`name` 속성**으로 값을 모읍니다. `name`이 없으면 전송되지 않습니다.
- 첫 전송 시 Formspree가 이메일 인증을 요구할 수 있습니다.
- 무료 요금제는 월 전송 횟수 제한이 있습니다.
- 실패 메시지는 성공 메시지와 다른 색으로 보이게 클래스를 따로 두면 좋습니다.

## 4. 시스템 다크 모드 감지 (`prefers-color-scheme`)
**우선순위: 사용자가 직접 고른 값(localStorage) > 시스템 설정 > 라이트**

```js
const systemDark = window.matchMedia("(prefers-color-scheme: dark)");

const state = {
    theme: localStorage.getItem("theme") || (systemDark.matches ? "dark" : "light"),
};

// (선택) 사용자가 직접 고른 적이 없을 때만 시스템 변경을 따라감
systemDark.addEventListener("change", (event) => {
    if (localStorage.getItem("theme")) return;
    state.theme = event.matches ? "dark" : "light";
    renderTheme();
});
```
- 4~5단계 가이드의 다크 모드 코드에서 `state` 초기값 한 줄만 바꾸면 됩니다.
- 확인 방법: macOS 시스템 설정 → 화면 모드 → 다크, 또는 F12 → `Cmd + Shift + P` → `Rendering` → **Emulate CSS prefers-color-scheme: dark**
- localStorage 값을 지우고 테스트해야 합니다: F12 → Application → Local Storage → `theme` 삭제

### (참고) 새로고침 시 하얗게 번쩍이는 문제
`defer` 스크립트는 화면을 그린 뒤 실행돼서, 다크 모드인데 잠깐 흰 화면이 보일 수 있습니다. 신경 쓰인다면 테마 적용 부분만 `<head>` 안에 작은 `<script>`로 먼저 실행하는 방법이 있습니다. (필수 아님)

# 13단계. 학습 목표 셀프 체크

**코드를 보지 않고 말로 설명할 수 있는지** 확인하는 단계입니다. 아래 질문에 먼저 스스로 답해 본 뒤, "답변 포인트"와 비교하세요. 막히는 질문은 해당 단계 가이드로 돌아가 복습합니다.

## Q1. 시맨틱 태그를 왜 쓰고, 어떤 기준으로 구조를 설계했나?
<details>
<summary>답변 포인트</summary>

- **의미 전달:** `<div>`는 아무 뜻이 없지만, `<nav>`는 "메뉴", `<main>`은 "본문"이라는 뜻이 있음
- **접근성:** 스크린리더가 "탐색 영역", "본문으로 건너뛰기" 등을 제공할 수 있음
- **검색 엔진(SEO):** 어디가 핵심 내용인지 파악하기 쉬움
- **가독성:** 코드만 봐도 구조가 보임
- **설계 기준:** 페이지 공통 상단 → `header`, 이동 메뉴 → `nav`, 페이지 고유 내용 → `main`, 주제별 구역 → `section`(제목 포함), 독립적으로 의미 있는 콘텐츠 → `article`(프로젝트 카드), 하단 정보 → `footer`
</details>

## Q2. Flexbox와 Grid의 차이, 각각 언제 쓰나?
<details>
<summary>답변 포인트</summary>

| | Flexbox | Grid |
|---|---|---|
| 방향 | **1차원** (가로 또는 세로 한 줄) | **2차원** (행과 열 동시에) |
| 기준 | 내용 크기에 맞춰 배치 | 미리 정한 틀(칸)에 배치 |
| 이 프로젝트 | 네비게이션 (로고 ↔ 메뉴), 버튼 묶음, 기술 스택 태그 | Projects 카드 목록 |

- `repeat(auto-fit, minmax(260px, 1fr))`: 카드 최소 폭을 지키면서 화면에 들어가는 만큼 열을 자동 생성 → 미디어 쿼리 없이 반응형
</details>

## Q3. `querySelector` → `addEventListener` 흐름을 설명해 보자
<details>
<summary>답변 포인트</summary>

1. 브라우저가 HTML을 읽어 **DOM 트리**를 만듦 (`defer`로 이 작업이 끝난 뒤 JS 실행)
2. `querySelector(".hamburger")`로 DOM에서 요소를 찾아 변수에 담음
3. `addEventListener("click", 함수)`로 "클릭되면 이 함수를 실행해 줘"라고 등록
4. 사용자가 클릭하면 브라우저가 등록된 함수를 호출
5. 함수 안에서 `classList.toggle` 등으로 DOM을 바꾸면 CSS가 다시 적용되어 화면이 변함

- `onclick` 속성 대신 쓰는 이유: HTML과 JS를 분리, 같은 요소에 여러 핸들러 등록 가능
- **이벤트 위임:** 나중에 생기는 요소(다시 시도 버튼, 필터 버튼)는 부모에 이벤트를 걸고 `event.target`으로 구분
</details>

## Q4. 화살표 함수, 구조분해 할당, `map` / `filter`는 왜 쓰나?
<details>
<summary>답변 포인트</summary>

- **화살표 함수:** 콜백을 짧게 씀 `repos.map((repo) => ...)`
- **구조분해 할당:** 객체에서 필요한 값만 이름 그대로 꺼냄 → `repo.name`, `repo.html_url`을 반복하지 않음
  `const { name, html_url, stargazers_count, language } = repo;`
- **`map`:** 데이터 배열 → 같은 길이의 새 배열 (저장소 데이터 → 카드 HTML)
- **`filter`:** 조건에 맞는 것만 남긴 새 배열 (포크 제외, 언어별 필터)
- 공통점: **원본 배열을 바꾸지 않고 새 배열을 돌려줌** → 상태를 안전하게 다룰 수 있음 (React에서도 같은 방식)
</details>

## Q5. `fetch` + `async/await`로 데이터를 가져오고, 상태를 UI로 어떻게 표현했나?
<details>
<summary>답변 포인트</summary>

- `fetch`는 **Promise**를 돌려줌 → 응답이 올 때까지 기다려야 함
- `async` 함수 안에서 `await`를 쓰면 기다리는 코드를 위에서 아래로 읽히게 쓸 수 있음
- 흐름: `status = "loading"` → 스피너 → `await fetch` → `response.ok` 확인 → `await response.json()` → 개수에 따라 `success` / `empty` → 실패 시 `catch`에서 `error`
- **`response.ok`를 직접 확인하는 이유:** `fetch`는 403/404여도 에러를 던지지 않고, 네트워크가 끊겼을 때만 `catch`로 감
- 403(레이트리밋)도 에러 상태로 처리, [다시 시도] 버튼으로 `fetchProjects()` 재호출
</details>

## Q6. 한 기능에서 이벤트 → 상태 변경 → DOM 업데이트가 어떻게 연결되나?
<details>
<summary>답변 포인트 (다크 모드 예시)</summary>

1. **이벤트:** 다크 모드 버튼 `click`
2. **상태 변경:** `state.theme = "dark"` + `localStorage.setItem("theme", "dark")`
3. **렌더링:** `renderTheme()`가 `document.documentElement.dataset.theme = state.theme` 실행
4. **화면:** `<html data-theme="dark">` → CSS `[data-theme="dark"]` 변수 적용 → 전체 색 변경

- 핵심 규칙: **화면을 직접 고치지 않고, 상태를 바꾼 뒤 render 함수를 부른다**
- React와 연결: `const [theme, setTheme] = useState("light")` → `setTheme("dark")` 하면 React가 알아서 다시 렌더링. 지금 만든 `state` + `render()`가 이걸 손으로 구현한 것
</details>
