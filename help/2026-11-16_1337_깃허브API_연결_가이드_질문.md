## 1. 현재 `js/script.js`에서 먼저 잡아야 할 부분

현재 `js/script.js` 114~128번째 줄을 보면 아래 3가지를 수정해야 정상 동작합니다.

1. **URL 오타 수정**
   - 현재: `'thhps://api.github.com/users/ghwo6/repos'`
   - 수정: `'https://api.github.com/users/ghwo6/repos'`
2. **`try / catch` 위치 합치기**
   - `try / catch`가 `fetchRepos` 함수 바깥에 따로 떨어져 있습니다.
   - `await`는 `async` 함수 안에서만 쓸 수 있으므로, `try / catch`를 `fetchRepos` 함수 **안으로** 넣어야 합니다.
3. **함수 호출하기**
   - `fetchRepos`를 선언만 하고 호출하지 않았기 때문에, 마지막에 `fetchRepos();`를 호출해야 페이지 로드 시 데이터를 가져옵니다.

## 2. `todolist.md` 기준 요구사항 정리

GitHub API 연동에서 반드시 들어가야 하는 핵심 요소입니다.

- **비동기 & 에러 처리 (`8번`)**
  - `fetch` + `async/await` + `try/catch` + `response.ok` 체크
  - **403 응답(레이트리밋 초과)** 포함해 실패 시 에러 상태 UI 표시
  - 4가지 상태 UI: **로딩 / 성공 / 에러([다시 시도] 버튼 포함) / 빈 상태**
- **ES6+ 문법 (`7번`)**
  - 화살표 함수, 템플릿 리터럴(`` `...` ``), 구조분해 할당 (`const { name, description, html_url, stargazers_count, language } = repo;`)
  - 배열 메서드 `map()`으로 데이터 배열 → HTML 카드 문자열 변환
- **상태 관리 패턴 (`9번`)**
  - **상태 객체(`projectState`)**와 **렌더링 함수(`renderProjects`)**를 분리해서 **"이벤트/API 결과 → 상태 변경 → 화면 업데이트"** 흐름이 보이게 작성
- **제약 사항 (`0번`)**
  - `var` 금지 (`const`, `let`만 사용)
  - HTML에 `onclick="..."` 금지 → `[다시 시도]` 버튼도 `addEventListener`로 연결
  - 인라인 `style="..."` 금지

> [!TIP]
> GitHub 비인증 API는 **시간당 60회** 제한(레이트리밋)이 있으므로, 개발 중 짧은 시간에 새로고침을 너무 많이 반복하지 않도록 주의하세요.

### Step 2. `js/script.js` — 상태 객체와 렌더링 함수 만들기

먼저 **상태(state)**가 어떻게 바뀔지 정의하고, 그 상태에 따라 화면을 그리는 `renderProjects()` 함수를 만듭니다.

```js
// DOM 요소 선택
const projectsStatus = document.querySelector('#projects-status');
const projectsGrid = document.querySelector('#projects-grid');

// 1. 상태(State) 정의
const projectState = {
    status: 'loading', // 'loading' | 'success' | 'error' | 'empty'
    repos: [],
    errorMessage: '',
};

// 2. 렌더링 함수 (상태 -> DOM 업데이트)
const renderProjects = () => {
    // 초기화
    projectsStatus.innerHTML = '';
    projectsGrid.innerHTML = '';

    if (projectState.status === 'loading') {
        projectsStatus.innerHTML = `
            <div class="spinner"></div>
            <p>프로젝트를 불러오는 중...</p>
        `;
        return;
    }

    if (projectState.status === 'error') {
        projectsStatus.innerHTML = `
            <p>${projectState.errorMessage}</p>
            <button type="button" id="retry-btn">다시 시도</button>
        `;
        // onclick 속성 대신 addEventListener 사용
        const retryBtn = document.querySelector('#retry-btn');
        retryBtn.addEventListener('click', fetchRepos);
        return;
    }

    if (projectState.status === 'empty') {
        projectsStatus.innerHTML = `<p>표시할 프로젝트가 없습니다.</p>`;
        return;
    }

    // success 상태: 구조분해 할당 + map + 템플릿 리터럴로 카드 생성
    projectsGrid.innerHTML = projectState.repos
        .map((repo) => {
            const { name, description, html_url, stargazers_count, language } = repo;
            return `
                <article class="project-card">
                    <h4>${name}</h4>
                    <p>${description || '설명이 없습니다.'}</p>
                    <div class="project-meta">
                        <span>${language || '기타'}</span>
                        <span>★ ${stargazers_count}</span>
                    </div>
                    <a href="${html_url}" target="_blank" rel="noopener noreferrer">GitHub 보기</a>
                </article>
            `;
        })
        .join('');
};
```

### Step 3. `js/script.js` — `fetchRepos` 함수로 API 호출 & 상태 변경

API 요청 전에는 `loading`으로, 응답 결과에 따라 `empty` / `success` / `error`로 상태를 바꾸고 `renderProjects()`를 호출합니다.

```js
const fetchRepos = async () => {
    const url = 'https://api.github.com/users/ghwo6/repos';

    // 요청 시작 -> 로딩 상태로 변경 후 렌더링
    projectState.status = 'loading';
    projectState.errorMessage = '';
    renderProjects();

    try {
        const response = await fetch(url);

        if (response.status === 403) {
            throw new Error('GitHub API 요청 한도(시간당 60회)를 초과했습니다. 잠시 후 다시 시도해 주세요.');
        }

        if (!response.ok) {
            throw new Error(`프로젝트를 불러올 수 없습니다. (HTTP ${response.status})`);
        }

        const repos = await response.json();

        if (repos.length === 0) {
            projectState.status = 'empty';
            projectState.repos = [];
        } else {
            projectState.status = 'success';
            projectState.repos = repos;
        }
    } catch (error) {
        projectState.status = 'error';
        projectState.errorMessage = error.message || '프로젝트를 불러올 수 없습니다.';
    }

    // 최종 상태 반영
    renderProjects();
};

// 페이지 로드시 실행
fetchRepos();
```

> [!NOTE]
> `map(...).join('')`에서 `.join('')`을 빼먹으면 카드 사이에 쉼표(`,`)가 화면에 출력되니 꼭 붙여 주세요!

## 5. 추가 Q&A: `href="${html_url}"` 에서 `""`로 감싼 이유

> **질문 (2026-11-16 14:01):** `<a href="${html_url}" target="_blank" ...>` 에서 `href` 값을 `""`로 감싼 이유가 뭐야?

결론부터 말하면, **JS의 템플릿 리터럴(`` `...` ``)이 최종적으로 만들어내는 결과물이 "HTML 코드 문자열"이기 때문**입니다.

1. **JS가 `${html_url}`을 치환한 뒤 브라우저에 들어가는 모습**
   - `html_url` 변수에 `'https://github.com/ghwo6/B01-01'`이 들어있다고 가정하면, JS가 변환한 최종 HTML은 아래와 같습니다.
   - `""`가 있는 경우:
     ```html
     <a href="https://github.com/ghwo6/B01-01" target="_blank">
     ```
   - `""`가 없는 경우:
     ```html
     <a href=https://github.com/ghwo6/B01-01 target="_blank">
     ```

2. **HTML 속성값을 `""`로 감싸야 하는 이유**
   - **값 안에 공백이나 특수문자가 있어도 안전함:** 만약 속성값에 공백이 들어가면, 따옴표가 없을 때 브라우저가 공백 뒤를 **다음 속성**으로 착각해 HTML이 깨집니다. (예: `alt=만화 캐릭터` → `alt="만화"`와 `캐릭터`라는 알 수 없는 속성으로 분리됨 / `alt="만화 캐릭터"`여야 정상 인식)
   - **HTML 표준 및 일관성:** `target="_blank"`, `class="project-card"`처럼 모든 HTML 속성은 `속성명="값"` 형태로 쓰는 것이 표준 관례이며 가독성도 좋습니다.
   - **백틱(`` ` ``) 안이라 충돌이 없음:** 바깥을 백틱(`` ` ``)으로 감쌌기 때문에, 안쪽의 HTML 속성에는 큰따옴표(`"`)를 `\"` 같은 이스케이프 없이 그대로 쓸 수 있습니다.

### B. `projectsStatus` vs `projectState` — 관심사(역할) 완전 구분하기

두 이름 모두 `project` + `Stat...`로 시작해서 스펠링이 비슷해 보이지만, **다루는 관심사(역할)가 완전히 다릅니다.**

| 이름 | 정체 | 관심사 (무엇을 담당하나?) | 비유 |
| :--- | :--- | :--- | :--- |
| **`projectsStatus`** | **DOM 요소** (`<div id="projects-status">`) | **"화면에 어디다 그릴까?"** (화면 / UI) | 글자를 적어 보여주는 **칠판** |
| **`projectState`** | **JS 객체** (`{ status, repos, errorMessage }`) | **"지금 어떤 상태고 무슨 데이터가 있나?"** (데이터) | 현재 상황을 적어두는 **머릿속 메모장** |

#### 둘은 어떻게 연결되나요?
1. **`fetchRepos()` (API 호출 함수):** 서버 응답을 받은 뒤 **`projectState`(메모장)**의 내용을 바꿉니다.
   - 예: `projectState.status = 'error'`, `projectState.errorMessage = '...'`
2. **`renderProjects()` (렌더링 함수):** **`projectState`(메모장)**를 읽어서, **`projectsStatus`(칠판)**에 HTML을 써넣습니다.
   - 예: `projectsStatus.innerHTML = '<p>...</p>'`

즉, **`projectState`는 "데이터(원인)"**이고, **`projectsStatus`는 그 데이터를 화면에 보여주는 "HTML 상자(결과가 출력되는 곳)"**입니다.

### C. 왜 이름을 그렇게 지었을까? & 안 헷갈리는 팁

- **`State`(상태 데이터):** React 같은 프론트엔드에서 *"시간에 따라 변하고 화면을 다시 그리게 만드는 데이터 묶음"*을 관례적으로 `State`라고 부릅니다. (`projectState`)
- **`Status`(진행 상태 표시 영역):** HTML의 `<div id="projects-status">`를 JS로 가져오다 보니 변수명도 똑같이 `projectsStatus`로 지은 것입니다.

하지만 실제로 코딩할 때 두 이름이 너무 비슷해서 `projectStatus`처럼 오타가 나기 쉽습니다. **이름만 봐도 DOM 요소인지 데이터인지 바로 구분하려면 아래처럼 접미사를 붙이는 습관**을 들이면 훨씬 편합니다.

- **DOM 요소** 뒤에는 **`El`**(Element) 붙이기 → `projectsStatusEl`, `projectsGridEl`
- **데이터 객체**는 그대로 **`State`** 유지 → `projectState`

이렇게 하면 `projectState`(데이터)와 `projectsStatusEl`(HTML 요소)가 한눈에 구분됩니다. *(단, 변수명을 바꾸면 선언한 곳과 사용하는 곳을 모두 같이 바꿔주어야 합니다.)*
